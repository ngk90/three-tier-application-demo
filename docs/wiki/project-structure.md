# Project Structure

This three-tier application is organized into four main directories under `src/`: the web frontend, REST API, database migrations, and infrastructure-as-code. Each layer is independently containerized and can be developed, tested, and deployed separately.

## Directory Layout

```
src/
├── api/            # Express REST API (Node.js)
├── db/             # Database migrations (node-pg-migrate)
├── web/            # Next.js frontend (React)
└── infrastructure/ # Terraform for GCP deployment
```

## Web Frontend (`src/web/`)

The frontend is a **Next.js 16** application with React 19 and Tailwind CSS, serving the user interface on port 3000.

| File/Folder | Purpose |
|-------------|---------|
| `app/` | Next.js App Router pages and components |
| `public/` | Static assets (images, fonts, etc.) |
| `package.json` | Dependencies and scripts |
| `next.config.ts` | Next.js configuration |
| `tsconfig.json` | TypeScript configuration |
| `Dockerfile` | Multi-stage build for production |
| `AGENTS.md` | AI agent instructions |

The frontend communicates with the API through HTTP requests and displays a task manager interface.

## API (`src/api/`)

The backend is an **Express 5** REST API running on port 3001, handling all business logic and database queries.

| File | Purpose |
|------|---------|
| `index.js` | Route handlers for `/health`, `/tasks`, and task operations |
| `db.js` | PostgreSQL connection pool configuration |
| `index.test.js` | Unit tests for API endpoints |
| `package.json` | Dependencies (Express, pg, etc.) |
| `Dockerfile` | Container image for the API service |

The API exposes endpoints for listing, creating, and updating tasks. See the [API Endpoints](API%20Endpoints.md) page for details.

## Database Migrations (`src/db/`)

Database schema changes are managed with **node-pg-migrate**, allowing version-controlled, reversible migrations.

| File/Folder | Purpose |
|-------------|---------|
| `migrations/` | SQL migration files (auto-numbered by timestamp) |
| `package.json` | node-pg-migrate and PostgreSQL client dependencies |
| `Dockerfile` | Runs migrations on container startup |

Migrations are applied automatically when the Docker Compose stack starts via the `migrate` service. See the [Database Migrations](Database%20Migrations.md) page for running migrations manually.

## Infrastructure as Code (`src/infrastructure/`)

**Terraform** configuration for deploying the application to Google Cloud Platform, provisioning all cloud resources.

| File | Purpose |
|------|---------|
| `main.tf` | VPC, Cloud SQL, Cloud Run, Secret Manager, IAM |
| `variables.tf` | Input variables (project ID, image URIs, region, environment) |
| `outputs.tf` | Output values (web URL, API URL, database connection) |
| `migration.tf` | Cloud Run job for running database migrations in GCP |
| `terraform.tfvars.example` | Example variable values (copy and customize) |

See the [Deployment to GCP](Deployment%20to%20GCP.md) page for deployment instructions.

## Docker Compose Orchestration

The `docker-compose.yml` at the repository root defines four services:

```yaml
services:
  postgres:   # PostgreSQL 17 database
  migrate:    # Runs migrations, then exits
  api:        # Express API (internal only)
  web:        # Next.js frontend (exposed on port 3000)
```

Services start in dependency order: postgres → migrate → api → web. The web frontend is the only service exposed to the host.
