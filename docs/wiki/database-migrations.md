# Database Migrations

_Generated by Forge from `main` at `9e9f20c`._

This application uses **node-pg-migrate** to manage database schema changes. Migration files in `src/db/migrations/` define incremental schema updates with reversible `up` and `down` functions. Migrations are applied automatically when the application starts via Docker Compose, and can be run manually or rolled back as needed.

## Overview

Database migrations provide version control for your PostgreSQL schema. Each migration file contains two functions:

- **`up`** — applies the schema change (create tables, add columns, etc.)
- **`down`** — reverts the change (drop tables, remove columns, etc.)

This ensures the database schema can be evolved safely and rolled back if needed.

## Migration Files

Migration files live in `src/db/migrations/` and follow the naming convention:

```
{timestamp}_{description}.js
```

For example:
- `1718500000000_initial-schema.js` — creates the `users` table
- `1718500001000_create-tasks.js` — creates the `tasks` table

Each file exports `up` and `down` functions that receive a `pgm` (migration helper) object:

```javascript
exports.up = (pgm) => {
  pgm.createTable('tasks', {
    id: { type: 'serial', primaryKey: true },
    title: { type: 'varchar(500)', notNull: true },
    completed: { type: 'boolean', notNull: true, default: false },
    created_at: { type: 'timestamp', notNull: true, default: pgm.func('now()') },
  });
};

exports.down = (pgm) => {
  pgm.dropTable('tasks');
};
```

## Running Migrations

### Automatic (Docker Compose)

When you run `docker compose up`, the `migrate` service automatically applies all pending migrations:

```bash
docker compose up --build
```

The service runs `node-pg-migrate up` and exits after completion. The database is ready for the API and web services.

### Manual (Local Development)

To run migrations manually, set the `DATABASE_URL` environment variable and use npm scripts:

```bash
cd src/db
DATABASE_URL=postgres://app:app@localhost:5432/app npm run migrate
```

The `DATABASE_URL` format is: `postgres://[user]:[password]@[host]:[port]/[database]`

## Common Tasks

| Task | Command |

| Roll back the last migration | `npm run migrate:down` |

| Create a new migration | `npx node-pg-migrate create {description}` |

## Creating a New Migration

To add a new migration, use the CLI:

```bash
cd src/db
npx node-pg-migrate create add_user_name_column
```

This generates a timestamped file in `src/db/migrations/` with `up` and `down` stubs. Edit the file to define your schema change:

```javascript
exports.up = (pgm) => {
  pgm.addColumn('users', {
    name: { type: 'varchar(255)' },
  });
};

exports.down = (pgm) => {
  pgm.dropColumn('users', 'name');
};
```

## Configuration

Migrations are configured in `src/db/package.json`:

```json
{
  "scripts": {
    "migrate": "node-pg-migrate up",
    "migrate:down": "node-pg-migrate down"
  },
  "dependencies": {
    "node-pg-migrate": "^8.0.4",
    "pg": "^8.21.0"
  }
}
```

The `node-pg-migrate` tool reads the `DATABASE_URL` environment variable to connect to PostgreSQL. In Docker, this is set in `docker-compose.yml`.

## Best Practices

- **Always write reversible migrations** — ensure `down` can undo `up`
- **One change per migration** — keep migrations focused and small
- **Test locally first** — run migrations on your local database before deploying
- **Never edit applied migrations** — create a new migration to fix mistakes
- **Use descriptive names** — make the migration purpose clear in the filename

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Migration fails with "relation already exists" | The migration may have been partially applied; check the `pgmigrations` table in the database |
| `DATABASE_URL` not found | Ensure the environment variable is set before running `npm run migrate` |
| Need to reset the database | Run `docker compose down -v` to delete the volume, then `docker compose up` to start fresh |
