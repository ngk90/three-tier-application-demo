# Database Migrations

This project uses [node-pg-migrate](https://salsita.github.io/node-pg-migrate/) to manage PostgreSQL schema changes in a version-controlled, reversible way. Each migration is a timestamped JavaScript file that defines `up` and `down` functions to apply and rollback changes. Migrations are automatically applied when the application starts via Docker Compose, and can be run manually for development or deployment workflows.

## Overview

Migrations in `src/db/migrations/` follow a naming convention: `{timestamp}_{description}.js`. The timestamp ensures migrations run in order, and the description documents the change. Each migration exports two functions:

- **`up(pgm)`** — applies the schema change
- **`down(pgm)`** — reverts the change (for rollback)

The `pgm` object is a helper from node-pg-migrate that provides methods like `createTable()`, `dropTable()`, `addColumn()`, and `dropColumn()`.

### Example: Create a Table

From `src/db/migrations/1718500001000_create-tasks.js`:

```javascript
exports.up = (pgm) => {
  pgm.createTable('tasks', {
    id: { type: 'serial', primaryKey: true },
    title: { type: 'varchar(500)', notNull: true },
    completed: { type: 'boolean', notNull: true, default: false },
    created_at: { type: 'timestamp', notNull: true, default: pgm.func('now()') },
  });
};

exports.down = (pgm) => {
  pgm.dropTable('tasks');
};
```

## Running Migrations

### Automatic (Docker Compose)

When you run `docker compose up`, the `migrate` service automatically applies all pending migrations before the API starts:

```bash
docker compose up --build
```

The `migrate` service runs once and exits. Check logs with:

```bash
docker compose logs migrate
```

### Manual (Development)

To run migrations manually, set the `DATABASE_URL` environment variable and use npm scripts from `src/db/`:

```bash
cd src/db
DATABASE_URL=postgres://app:app@localhost:5432/app npm run migrate
```

Or use `node-pg-migrate` directly:

```bash
npx node-pg-migrate up
```

### Rollback

To undo the last migration:

```bash
cd src/db
DATABASE_URL=postgres://app:app@localhost:5432/app npm run migrate:down
```

Or specify how many steps to roll back:

```bash
npx node-pg-migrate down --count=2
```

## Creating a New Migration

### Step 1: Generate the migration file

Use node-pg-migrate to create a timestamped file:

```bash
cd src/db
npx node-pg-migrate create add_user_name_column
```

This creates a file like `1718500002000_add_user_name_column.js` with a template.

### Step 2: Write the up and down functions

Edit the generated file to define your schema change:

```javascript
exports.up = (pgm) => {
  pgm.addColumn('users', 'name', {
    type: 'varchar(255)',
    notNull: false,
  });
};

exports.down = (pgm) => {
  pgm.dropColumn('users', 'name');
};
```

### Step 3: Test locally

Run the migration against your local database:

```bash
DATABASE_URL=postgres://app:app@localhost:5432/app npm run migrate
```

Verify the schema change in psql or your database client, then test the rollback:

```bash
npm run migrate:down
npm run migrate  # re-apply to confirm
```

### Step 4: Commit and push

```bash
git add src/db/migrations/
git commit -m "Add user name column"
git push
```

## Configuration

Migrations are configured via environment variables:

| Variable | Default | Purpose |
|----------|---------|---------|
| `DATABASE_URL` | (required) | PostgreSQL connection string |
| `PGMIGRATIONS_DIR` | `./migrations` | Directory containing migration files |
| `PGMIGRATIONS_TABLE` | `pgmigrations` | Table that tracks applied migrations |

The `DATABASE_URL` format is: `postgres://username:password@host:port/database`

## Deployment to GCP

When deploying to Google Cloud Platform via Terraform (`src/infrastructure/`), the migration runs as part of the Cloud Run initialization. The `migrate` service container is built from `src/db/Dockerfile` and executes before the API starts.

The database URL is injected from Secret Manager, so migrations automatically apply to the Cloud SQL instance without manual intervention.

## Troubleshooting

### Migration fails with "relation already exists"

A migration may have been partially applied. Check the `pgmigrations` table:

```sql
SELECT * FROM pgmigrations;
```

If a migration is stuck, you can manually delete its row (use caution):

```sql
DELETE FROM pgmigrations WHERE name = '1718500002000_add_user_name_column';
```

### Rollback fails

Ensure the `down` function is the exact inverse of `up`. Test rollback in development before deploying.

### Connection refused

Verify `DATABASE_URL` is set and the PostgreSQL server is running:

```bash
echo $DATABASE_URL
docker compose ps postgres
```
