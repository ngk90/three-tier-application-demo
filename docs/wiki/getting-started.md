Get the three-tier application running locally in seconds using Docker Compose. The entire stack—PostgreSQL database, Express API, and Next.js frontend—starts with a single command, with automatic database migrations and service orchestration.

## Prerequisites

You need Docker Desktop (or Docker Engine with the Compose plugin) installed on your machine. Download it from [docker.com](https://www.docker.com/products/docker-desktop/).

## Start the application

From the repository root, run:

```bash
docker compose up --build
```

This command builds and starts four services in dependency order:

| Service | Purpose | Port |
|---------|---------|------|
| **postgres** | PostgreSQL 17 database | internal only |
| **migrate** | Applies database schema migrations | — |
| **api** | Express REST API | 3001 (internal) |
| **web** | Next.js frontend | 3000 (exposed) |

The `--build` flag rebuilds container images from the Dockerfiles in `src/api/`, `src/db/`, and `src/web/`. Omit it on subsequent runs if you haven't changed code.

Once all services are healthy, open [http://localhost:3000](http://localhost:3000) in your browser.

## How it works

The `docker-compose.yml` file orchestrates the startup sequence:

1. **postgres** starts first and waits until it reports healthy via `pg_isready`
2. **migrate** waits for postgres to be healthy, then runs `node-pg-migrate up` to apply all pending migrations from `src/db/migrations/`
3. **api** waits for migrations to complete, then starts the Express server
4. **web** waits for the API to be ready, then starts the Next.js development server

The frontend communicates with the API via the internal Docker network at `http://api:3001` (see the `API_URL` environment variable in `docker-compose.yml`).

## Stop and clean up

Stop the containers while keeping the database volume:

```bash
docker compose down
```

Stop and delete all data (including the postgres_data volume):

```bash
docker compose down -v
```

## Rebuild after code changes

After modifying code in `src/api/`, `src/db/`, or `src/web/`, rebuild and restart:

```bash
docker compose up --build
```

For frontend-only changes during development, you can often rely on Next.js hot reload without rebuilding. For API or database changes, a rebuild is required.

## Accessing the API directly

The API is not exposed to your host machine by default (only to the web container). To test API endpoints directly, you can temporarily expose port 3001 by editing `docker-compose.yml`:

```yaml
api:
  # ... other config ...
  ports:
    - "3001:3001"
```

Then restart with `docker compose up`. See the [API Endpoints](API-Endpoints) page for available routes.

## Troubleshooting

**Containers fail to start:** Check Docker Desktop is running and has sufficient resources (at least 2 GB RAM, 2 CPU cores).

**Port 3000 already in use:** Stop other services using that port, or modify the `ports` mapping in `docker-compose.yml` to `"3001:3000"` (for example).

**Database migrations fail:** Check the logs with `docker compose logs migrate`. Ensure `src/db/migrations/` contains valid migration files.

**API cannot connect to database:** Verify the `DATABASE_URL` environment variable in `docker-compose.yml` matches the postgres credentials (`app:app@postgres:5432/app`).
