# Getting Started

_Generated by Forge from `main` at `9e9f20c`._

This page guides you through running the three-tier application locally using Docker Compose. The entire stack—PostgreSQL database, Express API, and Next.js frontend—starts with a single command and is ready to use within seconds.

## Prerequisites

You need Docker installed on your machine:

- **Docker Desktop** (recommended for macOS and Windows) — includes Docker Engine and Compose
- **Docker Engine + Compose plugin** (for Linux)

Download from [docker.com/products/docker-desktop](https://www.docker.com/products/docker-desktop/).

## Start the application

From the repository root, run:

```bash
docker compose up --build
```

This command builds and starts four services in dependency order:

| Service | Role | Status |
|---------|------|--------|
| **postgres** | PostgreSQL 17 database | Waits until healthy before proceeding |
| **migrate** | Runs database migrations | Exits after schema is applied |
| **api** | Express REST API on port 3001 | Starts after migrations complete |
| **web** | Next.js frontend on port 3000 | Starts after API is ready |

Once you see logs indicating the web service is running, open your browser to **[http://localhost:3000](http://localhost:3000)** and start using the application.

## How Docker Compose works

The `docker-compose.yml` file orchestrates the entire stack:

- **postgres** uses the official `postgres:17-alpine` image with a health check
- **migrate** runs a custom Docker image from `src/db/` that executes `node-pg-migrate up`
- **api** builds from `src/api/` and connects to the database via `DATABASE_URL`
- **web** builds from `src/web/`, exposes port 3000 to your host, and calls the API at `http://api:3001`

The `depends_on` directives ensure services start in the correct order and wait for readiness conditions.

## Stop and clean up

**Stop containers** (preserves database data):

```bash
docker compose down
```

**Stop and delete all data** (including the PostgreSQL volume):

```bash
docker compose down -v
```

## Rebuild after code changes

If you modify code in `src/api/`, `src/web/`, or `src/db/`, rebuild the images:

```bash
docker compose up --build
```

Omit `--build` to reuse existing images and only restart containers.

## Access the API

The API is not exposed to your host by default (only the web frontend is). To test API endpoints directly, you can:

- **Call from the web container** — the frontend already does this at `http://api:3001`
- **Temporarily expose the port** — modify `docker-compose.yml` to add `ports: ["3001:3001"]` under the `api` service, then restart

Common endpoints:

| Method | Path | Description |
|--------|------|-------------|
| GET | `/health` | Health check |
| GET | `/tasks` | List all tasks |
| POST | `/tasks` | Create a task (body: `{ "title": "..." }`) |
| PATCH | `/tasks/:id` | Update a task (body: `{ "completed": true }` or `{ "title": "..." }`) |

## Troubleshooting

**Port 3000 or 3001 already in use?**

Stop other services using those ports, or modify the port mappings in `docker-compose.yml`.

**Database won't start?**

Check Docker's disk space and memory allocation. Restart Docker Desktop and try again.

**Migrations fail?**

Ensure the `postgres` service is healthy before the `migrate` service runs. Check logs with `docker compose logs migrate`.

**Changes not reflected?**

Always use `docker compose up --build` after modifying code. Without `--build`, Docker reuses cached images.
