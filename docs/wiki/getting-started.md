# Getting Started

Get the three-tier application running locally in seconds using Docker Compose. A single command starts the PostgreSQL database, applies schema migrations, and launches the Express API and Next.js frontend.

## Prerequisites

You need Docker installed on your machine:

- **Docker Desktop** (includes Docker Engine and Compose plugin) — [download here](https://www.docker.com/products/docker-desktop/)
- Alternatively, Docker Engine + Compose plugin on Linux

## Start the application

Run this command from the repository root:

```bash
docker compose up --build
```

Docker Compose will start four services in order:

| Service | Purpose | Port |
|---------|---------|------|
| **postgres** | PostgreSQL 17 database | internal only |
| **migrate** | Runs schema migrations, then exits | — |
| **api** | Express REST API | 3001 (internal) |
| **web** | Next.js frontend | 3000 (exposed) |

The `--build` flag rebuilds images from the Dockerfiles in `src/api/`, `src/db/`, and `src/web/`. Omit it on subsequent runs if you haven't changed code.

### First run

The first time you run the stack, Docker will:

1. Pull the PostgreSQL 17 image
2. Build the migrate, api, and web images
3. Start postgres and wait for it to be healthy (healthcheck in `docker-compose.yml`)
4. Run migrations to set up the database schema
5. Start the API and web services

This takes 1–2 minutes. Watch the logs for any errors.

### Open the application

Once all services are running, open your browser to:

```
http://localhost:3000
```

You should see the task manager interface. The frontend communicates with the API at `http://api:3001` (internal Docker network).

## Common tasks

### Stop the application

```bash
# Stop containers (keeps the postgres_data volume)
docker compose down

# Stop and delete all data
docker compose down -v
```

### Rebuild after code changes

```bash
docker compose up --build
```

This rebuilds the images and restarts all services. Use `--build` whenever you change code in `src/api/`, `src/db/`, or `src/web/`.

### View logs

```bash
# All services
docker compose logs -f

# Specific service
docker compose logs -f api
docker compose logs -f web
docker compose logs -f postgres
```

### Access the database directly

If you need to query the database directly:

```bash
docker compose exec postgres psql -U app -d app
```

Then run SQL commands like `SELECT * FROM tasks;`

## API endpoints

The API is not exposed to your host machine by default (only accessible from the web container). However, you can test it by temporarily mapping the port or using the web frontend. The available endpoints are:

| Method | Path | Description |
|--------|------|-------------|
| GET | `/health` | Health check |
| GET | `/tasks` | List all tasks |
| POST | `/tasks` | Create a task (body: `{ "title": "..." }`) |
| PATCH | `/tasks/:id` | Update a task (body: `{ "completed": true }` or `{ "title": "..." }`) |

See the [API Endpoints](API%20Endpoints) page for details.

## Troubleshooting

**Port 3000 or 3001 already in use**

If another application is using these ports, either stop it or modify `docker-compose.yml` to use different ports. For example, change `ports: - "3000:3000"` to `ports: - "3001:3000"` to access the web app on port 3001.

**Migrations fail**

Check the logs: `docker compose logs migrate`. Common issues:
- Database is not healthy yet — wait a few seconds and retry
- Schema conflicts — run `docker compose down -v` to delete the volume and start fresh

**API returns 500 errors**

Check the API logs: `docker compose logs api`. Ensure the database is running and migrations have completed.
