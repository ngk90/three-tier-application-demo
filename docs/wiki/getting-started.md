# Getting Started

This page walks you through running the three-tier task manager application locally using Docker Compose. Within minutes, you'll have the Next.js frontend, Express API, and PostgreSQL database running on your machine.

## Prerequisites

You need Docker installed on your system:

- **Docker Desktop** (includes Docker Engine and Compose plugin) — [download here](https://www.docker.com/products/docker-desktop/)
- Alternatively, Docker Engine + Compose plugin on Linux

## Starting the Application

Clone the repository and start all services with a single command:

```bash
docker compose up --build
```

This command builds and starts four services in dependency order:

| Service | Role | Status |
|---------|------|--------|
| **postgres** | PostgreSQL 17 database | Waits until healthy before proceeding |
| **migrate** | Runs schema migrations | Exits after applying all pending migrations |
| **api** | Express REST API on port 3001 | Internal only (not exposed to host) |
| **web** | Next.js frontend on port 3000 | Exposed to your browser |

Once you see logs indicating the services are running, open your browser to **[http://localhost:3000](http://localhost:3000)** and start creating tasks.

## How It Works

The `docker-compose.yml` file orchestrates the entire stack:

- **postgres** uses a health check to ensure the database is ready before migrations run
- **migrate** depends on postgres being healthy, then applies all pending migrations from `src/db/migrations/` and exits
- **api** waits for migrations to complete successfully before starting
- **web** connects to the API via the internal hostname `http://api:3001`

Each service has its own `Dockerfile` in `src/api/`, `src/db/`, and `src/web/`.

## Accessing the Application

| Component | URL | Notes |
|-----------|-----|-------|
| **Frontend** | http://localhost:3000 | Task manager UI in your browser |
| **API** | http://localhost:3001 | Not directly exposed; access through the frontend or temporarily map the port |
| **Database** | localhost:5432 | PostgreSQL; credentials are `app` / `app` |

The frontend communicates with the API using the environment variable `API_URL=http://api:3001` (set in `docker-compose.yml`).

## Common Commands

### Rebuild after code changes

```bash
docker compose up --build
```

### Stop containers (keeps database data)

```bash
docker compose down
```

### Stop and delete all data

```bash
docker compose down -v
```

This removes the `postgres_data` volume, so the database will be empty on the next `docker compose up`.

### View logs

```bash
# All services
docker compose logs -f

# Specific service
docker compose logs -f api
docker compose logs -f web
```

### Access the database directly

```bash
docker compose exec postgres psql -U app -d app
```

## Troubleshooting

**Port 3000 or 3001 already in use?**  
Edit `docker-compose.yml` and change the port mapping for `web`:
```yaml
ports:
  - "3001:3000"  # Access frontend at http://localhost:3001
```

**Migrations failed?**  
Check the migrate service logs:
```bash
docker compose logs migrate
```

**Database data persists between restarts?**  
The `postgres_data` volume is preserved by default. Use `docker compose down -v` to delete it.

**Changes to code not reflected?**  
Run `docker compose up --build` to rebuild the images.
