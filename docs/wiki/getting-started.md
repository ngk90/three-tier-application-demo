# Getting Started

_Generated by Forge from `main` at `9e9f20c`._

This page guides you through running the three-tier application locally using Docker Compose. With a single command, you'll have the Next.js frontend, Express API, and PostgreSQL database running and ready to use.

## Prerequisites

Before you begin, ensure you have the following installed:

- **Docker Desktop** (or Docker Engine + Compose plugin) — [Download here](https://www.docker.com/products/docker-desktop/)

That's all you need. Docker Compose handles the rest.

## Starting the application

Run the following command from the repository root:

```bash
docker compose up --build
```

This command builds and starts four services in sequence:

| Service | Purpose | Status |
|---------|---------|--------|
| **postgres** | PostgreSQL 17 database | Waits until healthy before proceeding |
| **migrate** | Applies database schema migrations | Runs once, then exits |
| **api** | Express REST API on port 3001 | Internal only (not exposed to host) |
| **web** | Next.js frontend on port 3000 | Exposed to your browser |

Once all services are running, open your browser to **[http://localhost:3000](http://localhost:3000)** to access the task manager application.

## Stopping and cleaning up

To stop the containers while preserving the database volume:

```bash
docker compose down
```

To stop and delete all data (including the database):

```bash
docker compose down -v
```

## Rebuilding after code changes

If you modify code in `src/api/`, `src/web/`, or `src/db/`, rebuild the images:

```bash
docker compose up --build
```

## Accessing the API

The API is not directly exposed to your host machine by default. However, you can interact with it in two ways:

1. **Through the web frontend** — The Next.js app at `http://localhost:3000` communicates with the API internally.
2. **Temporarily expose the API port** — Edit `docker-compose.yml` to add `ports: ["3001:3001"]` under the `api` service, then restart.

### Available endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/health` | Health check |
| GET | `/tasks` | List all tasks |
| POST | `/tasks` | Create a task (body: `{ "title": "..." }`) |
| PATCH | `/tasks/:id` | Update a task (body: `{ "completed": true }` or `{ "title": "..." }`) |

## Troubleshooting

**Containers fail to start:**
- Ensure Docker Desktop is running.
- Check that ports 3000 and 5432 are not already in use.
- Run `docker compose logs` to see detailed error messages.

**Database connection errors:**
- The `migrate` service waits for PostgreSQL to be healthy. If migrations fail, check the logs: `docker compose logs migrate`.
- The database credentials are hardcoded for local development: user `app`, password `app`, database `app`.

**Changes not reflected:**
- Always use `docker compose up --build` after modifying code to rebuild images.
