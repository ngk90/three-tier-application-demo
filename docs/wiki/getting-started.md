# Getting Started

_Generated by Forge from `main` at `066e1ef`._

This page guides you through running the three-tier application locally using Docker Compose. The entire stack—frontend, API, and database—starts with a single command, and you'll have a working task manager application running on your machine in minutes.

## Prerequisites

Before you begin, ensure you have:

- **Docker Desktop** (or Docker Engine + Compose plugin) — [download here](https://www.docker.com/products/docker-desktop/)

That's it. No need to install Node.js, PostgreSQL, or other dependencies separately; everything runs in containers.

## Start the application

From the repository root, run:

```bash
docker compose up --build
```

This command builds and starts four services in order:

1. **postgres** — PostgreSQL 17 database (waits until healthy)
2. **migrate** — applies database schema migrations, then exits
3. **api** — Express REST API on port 3001 (internal only)
4. **web** — Next.js frontend on port 3000 (exposed to your host)

Once you see logs indicating the services are running, open your browser to:

```
http://localhost:3000
```

You should see the task manager application. Create, update, and complete tasks to verify the full stack is working.

## How it works

The `docker-compose.yml` file orchestrates the services:

- **postgres** uses a health check to ensure the database is ready before other services start
- **migrate** depends on postgres being healthy, runs migrations, and exits
- **api** depends on migrate completing successfully
- **web** depends on api being ready, and exposes port 3000 to your machine

The web frontend communicates with the API via the internal Docker network at `http://api:3001`.

## Stop and clean up

To stop the application while keeping your data:

```bash
docker compose down
```

To stop and delete all data (including the database volume):

```bash
docker compose down -v
```

## Rebuild after code changes

If you modify code in `src/api/`, `src/web/`, or `src/db/`, rebuild and restart:

```bash
docker compose up --build
```

Docker will rebuild only the affected images and restart the services.

## Access the API directly

The API is not exposed to your host by default (only the web frontend is). To test API endpoints directly, you can:

- Use the web frontend UI (recommended for normal use)
- Temporarily expose the API port by editing `docker-compose.yml` and adding `ports: ["3001:3001"]` under the `api` service
- Make requests from inside the web container using `http://api:3001`

Common endpoints are documented in the [API Endpoints](API-Endpoints) page.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Port 3000 or 3001 already in use | Stop other services using those ports, or edit `docker-compose.yml` to use different ports |
| Database migration fails | Check logs with `docker compose logs migrate` and ensure the postgres service is healthy |
| Changes to code don't appear | Run `docker compose up --build` to rebuild images |
| Want a fresh database | Run `docker compose down -v` to delete the volume, then `docker compose up --build` |
