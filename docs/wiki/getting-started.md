# Getting Started

Get the three-tier task manager application running locally in seconds using Docker Compose. The entire stack—frontend, API, and database—starts with a single command, and you'll be managing tasks in your browser within moments.

## Prerequisites

Before you begin, ensure you have Docker installed on your system:

- **Docker Desktop** (recommended for Windows and macOS) — includes Docker Engine and Compose plugin
- **Docker Engine + Compose plugin** (for Linux)

Download from [docker.com/products/docker-desktop](https://www.docker.com/products/docker-desktop/).

## Start the application

From the repository root, run:

```bash
docker compose up --build
```

This command builds and starts four services in order:

| Service | Role | Port | Status |
|---------|------|------|--------|
| **postgres** | PostgreSQL 17 database | 5432 (internal) | Waits until healthy |
| **migrate** | Applies database schema | — | Runs once, then exits |
| **api** | Express REST API | 3001 (internal) | Starts after migrations complete |
| **web** | Next.js frontend | 3000 | Exposed to your browser |

Once all services are running, open your browser and navigate to:

```
http://localhost:3000
```

You'll see the task manager interface. Create, update, and complete tasks—the frontend communicates with the API, which reads and writes to PostgreSQL.

## Stopping and cleaning up

### Keep data between runs

```bash
docker compose down
```

This stops all containers but preserves the `postgres_data` volume, so your tasks persist.

### Delete everything

```bash
docker compose down -v
```

The `-v` flag removes all volumes, including the database. Use this to start fresh.

## Rebuilding after code changes

If you modify code in `src/api/`, `src/web/`, or `src/db/`, rebuild the images:

```bash
docker compose up --build
```

Docker will detect changes and rebuild only the affected services.

## Accessing the API directly

The API is not exposed to your host by default (only the web frontend is). To test API endpoints directly, you have two options:

**Option 1: Use the web container's network**

From inside the web container, the API is reachable at `http://api:3001`.

**Option 2: Temporarily expose the API port**

Edit `docker-compose.yml` and add a `ports` section to the `api` service:

```yaml
api:
  # ... existing config ...
  ports:
    - "3001:3001"
```

Then restart with `docker compose up`. You can now call `http://localhost:3001/health` from your host.

## Common tasks

| Task | Command |
|------|---------|
| View logs from all services | `docker compose logs -f` |
| View logs from one service | `docker compose logs -f api` |
| Run a command in the web container | `docker compose exec web sh` |
| Restart a specific service | `docker compose restart api` |

## Troubleshooting

**"Port 3000 is already in use"**

Another application is using port 3000. Either stop that application or change the port in `docker-compose.yml`:

```yaml
web:
  ports:
    - "3001:3000"  # Access at http://localhost:3001
```

**"postgres service fails to start"**

Check that Docker has sufficient disk space and memory. Try `docker system prune` to free up resources.

**"migrate service fails"**

The database migrations may have an error. View the logs:

```bash
docker compose logs migrate
```
