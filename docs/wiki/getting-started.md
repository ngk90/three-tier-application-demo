# Getting Started

This page walks you through setting up the local development environment and running the three-tier application using Docker Compose. The entire stack—frontend, API, and database—runs in containers with a single command.

## Prerequisites

Before you begin, ensure you have the following installed:

- **Docker Desktop** (or Docker Engine + Compose plugin) — [Download here](https://www.docker.com/products/docker-desktop/)

That's it! Docker Compose handles all dependencies, including Node.js, PostgreSQL, and npm packages.

## Starting the Application

Clone the repository and start the stack:

```bash
git clone https://github.com/ngk90/three-tier-application-demo.git
cd three-tier-application-demo
docker compose up --build
```

The `--build` flag rebuilds images from the Dockerfiles in `src/api/`, `src/db/`, and `src/web/`.

### What Happens on Startup

Docker Compose starts four services in dependency order:

| Service | Role | Port | Status |
|---------|------|------|--------|
| **postgres** | PostgreSQL 17 database | 5432 (internal) | Waits until healthy |
| **migrate** | Runs schema migrations | — | Exits after completion |
| **api** | Express REST API | 3001 (internal) | Starts after migrations succeed |
| **web** | Next.js frontend | 3000 (exposed) | Starts after API is ready |

Once all services are running, you'll see output like:

```
web_1  | ▲ Next.js 16.0.0
web_1  | - Local:        http://localhost:3000
```

Open your browser to **[http://localhost:3000](http://localhost:3000)** to access the task manager application.

## Stopping and Cleaning Up

### Stop containers (keep data)

```bash
docker compose down
```

This stops all containers but preserves the `postgres_data` volume, so your database persists.

### Stop and delete all data

```bash
docker compose down -v
```

The `-v` flag removes all volumes, including the database.

## Rebuilding After Code Changes

If you modify code in `src/api/`, `src/web/`, or `src/db/`, rebuild and restart:

```bash
docker compose up --build
```

For frontend changes, Next.js hot-reloads automatically. For API or database changes, a rebuild is required.

## Accessing the API

The API runs on port 3001 but is not exposed to your host by default. You can access it in two ways:

### Option 1: Through the web container (default)

The Next.js frontend communicates with the API via the internal network at `http://api:3001`.

### Option 2: Expose the API port

Edit `docker-compose.yml` to expose the API:

```yaml
api:
  # ... existing config ...
  ports:
    - "3001:3001"
```

Then restart with `docker compose up`. You can now call the API directly:

```bash
curl http://localhost:3001/health
```

## Common API Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/health` | Health check |
| GET | `/tasks` | List all tasks |
| POST | `/tasks` | Create a task (body: `{ "title": "..." }`) |
| PATCH | `/tasks/:id` | Update a task (body: `{ "completed": true }` or `{ "title": "..." }`) |

## Troubleshooting

### Containers fail to start

Check logs for all services:

```bash
docker compose logs
```

Or for a specific service:

```bash
docker compose logs api
docker compose logs web
docker compose logs postgres
```

### Port 3000 or 3001 already in use

Stop other services using those ports, or modify `docker-compose.yml` to use different ports.

### Database connection errors

Ensure the `postgres` service is healthy:

```bash
docker compose ps
```

The `postgres` service should show `(healthy)`. If not, check logs:

```bash
docker compose logs postgres
```

### Migrations fail

The `migrate` service runs automatically but may fail if the database schema is corrupted. Reset the database:

```bash
docker compose down -v
docker compose up --build
```
