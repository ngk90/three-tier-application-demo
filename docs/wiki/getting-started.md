This page guides you through running the three-tier application locally using Docker Compose. Within minutes, you'll have the task manager frontend, REST API, and PostgreSQL database running on your machine and accessible at `http://localhost:3000`.

## Prerequisites

You need [Docker Desktop](https://www.docker.com/products/docker-desktop/) (or Docker Engine with the Compose plugin) installed on your system. No other dependencies are required—Docker handles Node.js, PostgreSQL, and all runtime environments.

## Starting the application

From the repository root, run:

```bash
docker compose up --build
```

Docker Compose will start four services in order:

| Service | Role | Port | Status |
|---------|------|------|--------|
| **postgres** | PostgreSQL 17 database | 5432 (internal) | Waits until healthy |
| **migrate** | Runs schema migrations | — | Exits after completion |
| **api** | Express REST API | 3001 (internal) | Starts after migrations succeed |
| **web** | Next.js frontend | 3000 | Exposed to your browser |

Once all services are running, open your browser to **[http://localhost:3000](http://localhost:3000)** and you'll see the task manager interface.

## Using the application

The task manager is a simple to-do list. You can:

- **View tasks** — All tasks are fetched from the API and displayed on page load
- **Create a task** — Enter a title and click "Add Task"
- **Mark complete** — Click the checkbox next to a task to toggle its completion status
- **Edit a task** — Click the title to edit it

The frontend communicates with the API at `http://api:3001` (internal Docker network), which queries the PostgreSQL database.

## Stopping and cleaning up

To stop the containers while keeping your data:

```bash
docker compose down
```

To stop and delete all data (including the database volume):

```bash
docker compose down -v
```

## Rebuilding after code changes

If you modify code in `src/web/`, `src/api/`, or `src/db/`, rebuild and restart:

```bash
docker compose up --build
```

Docker will rebuild only the affected images and restart the services.

## Accessing the API directly

The API is not exposed to your host by default (only accessible from within the Docker network). To test API endpoints directly, you can temporarily expose port 3001 by editing `docker-compose.yml`:

```yaml
api:
  # ... other config ...
  ports:
    - "3001:3001"
```

Then restart with `docker compose up`. See the [API Endpoints](API-Endpoints) page for the full list of routes.

## Troubleshooting

**Containers won't start:** Check that Docker Desktop is running and ports 3000 and 5432 are not in use by other services.

**Database connection errors:** The `migrate` service may fail if PostgreSQL is not healthy. Check logs with `docker compose logs migrate`.

**Port already in use:** If port 3000 is taken, edit `docker-compose.yml` to map a different port (e.g., `"3001:3000"`).

**Rebuild not picking up changes:** Use `docker compose up --build` to force a rebuild, or `docker compose down -v && docker compose up --build` to start fresh.
