The application uses PostgreSQL 17 with schema managed through [node-pg-migrate](https://salsita.github.io/node-pg-migrate/), a lightweight migration tool that tracks applied migrations in a `pgmigrations` table. Migrations are version-controlled JavaScript files in `src/db/migrations/` that define the `up` (apply) and `down` (rollback) functions. The Docker Compose setup automatically runs pending migrations on startup via the `migrate` service.

## Schema Overview

The database currently contains two tables: `users` and `tasks`. Both use auto-incrementing serial primary keys and timestamp tracking.

| Table | Purpose | Key Columns |
|-------|---------|-------------|
| `users` | User accounts (reserved for future use) | `id`, `email`, `created_at` |
| `tasks` | To-do items | `id`, `title`, `completed`, `created_at` |

## Tasks Table

The `tasks` table stores individual task records for the application's to-do list feature.

```sql
CREATE TABLE tasks (
  id serial PRIMARY KEY,
  title varchar(500) NOT NULL,
  completed boolean NOT NULL DEFAULT false,
  created_at timestamp NOT NULL DEFAULT now()
);
```

**Columns:**

- `id` — Auto-incrementing primary key
- `title` — Task description (up to 500 characters, required)
- `completed` — Boolean flag; defaults to `false` when a task is created
- `created_at` — Timestamp of task creation; automatically set to current time

## Migration System

Migrations are managed with `node-pg-migrate` and live in `src/db/migrations/`. Each migration file is named with a timestamp prefix (e.g., `1718500001000_create-tasks.js`) to ensure deterministic ordering.

### Migration Structure

Each migration exports two functions:

```javascript
exports.up = (pgm) => {
  // Apply schema changes
};

exports.down = (pgm) => {
  // Rollback schema changes
};
```

The `pgm` object provides helper methods like `createTable()`, `dropTable()`, `addColumn()`, and `createIndex()`.

### Running Migrations

**Locally with Docker Compose:**

```bash
docker compose up
```

The `migrate` service automatically runs `node-pg-migrate up` on startup and applies all pending migrations.

**Manually (with `DATABASE_URL` set):**

```bash
cd src/db
# Apply all pending migrations
npx node-pg-migrate up

# Roll back the last migration
npx node-pg-migrate down
```

**Via npm scripts in `src/db/package.json`:**

```bash
npm run migrate      # Apply pending migrations
npm run migrate:down # Rollback last migration
```

## Migration Tracking

node-pg-migrate automatically creates a `pgmigrations` table to track which migrations have been applied. This prevents re-running migrations and ensures idempotency across environments (local, staging, production).

## Adding a New Migration

To add a new migration, create a file in `src/db/migrations/` with a new timestamp prefix:

```bash
cd src/db
npx node-pg-migrate create add_user_id_to_tasks
```

This generates a template file. Edit it to define your schema changes in the `up` and `down` functions, then commit and deploy.
