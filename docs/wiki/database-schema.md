The application uses PostgreSQL 17 with schema managed by [node-pg-migrate](https://salsita.github.io/node-pg-migrate/), a lightweight migration tool for Node.js. Migrations are append-only SQL scripts stored in `src/db/migrations/` and applied automatically on startup via the `migrate` Docker service. This ensures the database schema is always in sync with the application code.

## Migration System

Migrations are managed with **node-pg-migrate** (`src/db/package.json`), which tracks applied migrations in a `pgmigrations` table and prevents re-running the same migration twice. Each migration file exports `up` and `down` functions to apply and roll back changes.

### Running Migrations

Migrations run automatically when the application starts via Docker Compose:

```bash
docker compose up
```

The `migrate` service (defined in `docker-compose.yml`) runs `npx node-pg-migrate up` against the running PostgreSQL instance and exits once complete.

To run migrations manually:

```bash
cd src/db
DATABASE_URL=postgres://app:app@localhost:5432/app npx node-pg-migrate up
```

To roll back the last migration:

```bash
DATABASE_URL=postgres://app:app@localhost:5432/app npx node-pg-migrate down
```

## Migration Naming Convention

Migration files use a timestamp-based naming scheme: `{TIMESTAMP}_{description}.js`. The timestamp ensures migrations run in order, and the description documents the change:

- `1718500000000_initial-schema.js` — Creates the `users` table
- `1718500001000_create-tasks.js` — Creates the `tasks` table

When adding a new migration, use a Unix timestamp (in milliseconds) that is greater than the previous migration's timestamp.

## Docker Setup

The migration service runs in a dedicated container (`src/db/Dockerfile`) that:

1. Installs dependencies from `src/db/package.json`
2. Copies migration files from `src/db/migrations/`
3. Runs `node-pg-migrate up` against the database

The container exits after migrations complete, and the API service then starts and connects to the initialized database.

## Adding New Migrations

To add a new migration:

1. Create a new file in `src/db/migrations/` with a timestamp greater than the last migration:
   ```bash
   touch src/db/migrations/1718500002000_add-user-id-to-tasks.js
   ```

2. Export `up` and `down` functions:
   ```javascript
   exports.up = (pgm) => {
     pgm.addColumn('tasks', {
       user_id: { type: 'integer', references: 'users(id)' },
     });
   };

   exports.down = (pgm) => {
     pgm.dropColumn('tasks', 'user_id');
   };
   ```

3. Rebuild and restart the application:
   ```bash
   docker compose up --build
   ```
