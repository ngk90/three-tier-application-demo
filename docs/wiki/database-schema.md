## Migration System

The project uses **node-pg-migrate** (`src/db/package.json`) to manage database schema changes. Each migration file exports `up` and `down` functions that define forward and rollback operations.

### Running Migrations

**Automatically (Docker Compose):**
The `migrate` service in `docker-compose.yml` runs all pending migrations before the API starts:
```bash
docker compose up
```

**Manually:**
```bash
cd src/db
DATABASE_URL=postgres://app:app@localhost:5432/app npx node-pg-migrate up
```

**Rollback the last migration:**
```bash
DATABASE_URL=postgres://app:app@localhost:5432/app npx node-pg-migrate down
```

## Docker Migration Service

The `src/db/Dockerfile` builds a lightweight migration runner:

```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci --omit=dev
COPY migrations ./migrations
CMD ["npx", "node-pg-migrate", "up"]
```

This service:
- Uses Node.js 22 Alpine for a minimal image
- Installs only production dependencies (`--omit=dev`)
- Copies migration files into the container
- Runs `node-pg-migrate up` on startup

In `docker-compose.yml`, the `migrate` service depends on `postgres` being healthy and runs before the API starts, ensuring the schema is always up-to-date.

## Adding New Migrations

To create a new migration:

```bash
cd src/db
npx node-pg-migrate create <description>
```

This generates a new file in `src/db/migrations/` with a timestamp prefix. Edit the file to define your schema changes:

```javascript
exports.up = (pgm) => {
  // Define forward migration
  pgm.addColumn('tasks', 'priority', { type: 'int', default: 0 });
};

exports.down = (pgm) => {
  // Define rollback
  pgm.dropColumn('tasks', 'priority');
};
```
