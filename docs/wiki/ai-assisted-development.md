# AI-Assisted Development

This three-tier application is designed to work well with Claude Code and other AI agents. The codebase has clear boundaries between layers, explicit conventions, and patterns that make it easy for AI tools to understand and modify. This page covers best practices for using Claude Code to develop features, understand the architecture, and maintain the application.

## Getting Started with Claude Code

Claude Code is a CLI tool that reads your codebase, executes commands, edits files, and reasons about multi-file changes. Install it and open the repository:

```bash
npm install -g @anthropic-ai/claude-code
cd three-tier-application-demo
claude
```

Claude Code automatically reads the project structure. It works best when you provide specific, scoped tasks rather than broad requests. For example, instead of "add a feature," say "add a DELETE /tasks/:id endpoint to the API and wire it up to a delete button in the frontend."

## Effective Prompting Patterns

### Understanding the Codebase

Use these prompts to explore how the application works:

- "Explain how a task flows from the browser through the web tier, to the API, and into the database."
- "What tables exist in the database and what are their schemas?"
- "Walk me through what happens when `docker compose up` runs, in order."
- "Review the API's error handling. Are there cases where the server could crash or return an unhelpful error?"

### Adding Features

Break feature requests into specific, actionable tasks:

- "Add a DELETE /tasks/:id endpoint to the API and wire it up to a delete button in the frontend."
- "Add a due_date column to the tasks table. Create the migration, update the API to accept and return it, and show it in the UI."
- "Add input validation to the POST /tasks endpoint so that titles longer than 200 characters are rejected with a 422 status."

### Database Migrations

Migrations are a common task for AI agents:

- "Create a node-pg-migrate migration that adds a priority column (integer, default 0) to the tasks table."
- "Show me all the migrations that have been applied and what schema they created."

### Docker and Infrastructure

AI agents can help with deployment and configuration:

- "The migrate service keeps restarting. Read the Dockerfile and docker-compose.yml and tell me why."
- "Add a .env.example file documenting all environment variables used across the three services."
- "Explain the Terraform in `src/infrastructure/` and what GCP resources it creates."

## Best Practices for AI-Assisted Development

### Provide Context, Not Just Commands

**Ineffective:** "Fix the bug"

**Effective:** "The PATCH /tasks/:id endpoint returns 200 even when the id doesn't exist. Fix it to return 404."

Telling Claude Code which endpoint, file, or component you're referring to and what the expected behavior is saves round-trips and produces better results.

### Scope Changes to One Tier at a Time

Three-tier applications have natural seams at each layer boundary. When adding a feature, ask Claude to work on one layer at a time and verify each before moving on:

1. **Migration first** — get the schema right
2. **API next** — add the endpoint and test it with curl
3. **Frontend last** — wire up the UI

This approach reduces the risk of cascading errors and makes it easier to debug issues.

### Let Claude Run the Application

Claude Code can execute `docker compose up` and observe logs. If something breaks at runtime, ask:

```
Run docker compose up and tell me what errors appear in the logs.
```

This is especially useful for catching runtime errors that static analysis might miss.

### Use It to Write One-Off Scripts

For tasks like seeding data or inspecting the database:

```
Write a script that seeds the tasks table with 10 sample tasks using the API's POST /tasks endpoint.
```

### Ask for Explanations Before Risky Changes

Before making significant changes (schema migrations, refactors, authentication), ask Claude to explain its plan first:

```
Before you make any changes, explain your plan for adding user authentication to this app.
```

This gives you a chance to review the approach and catch potential issues early.

## Project-Specific Conventions

When working with Claude Code on this project, keep these conventions in mind:

| Convention | Details |
|-----------|---------|
| **Migrations are append-only** | Never edit an existing migration file in `src/db/migrations/`; create a new one instead. |
| **The API is internal** | The API is not exposed outside the Docker network; all external traffic goes through the web tier. |
| **Environment variables are the config boundary** | Connection strings, ports, and URLs are all passed via env vars. No hardcoded values. |
| **Node 22 / PostgreSQL 17** | Match these versions in any new Dockerfiles or dependencies. |
| **Next.js version matters** | The web tier uses a specific version of Next.js with potentially breaking changes. Read `src/web/AGENTS.md` before writing code. |

## Common Workflows

### Adding a New Task Property

To add a new column to tasks (e.g., `priority`):

1. Ask Claude to create a migration: "Create a node-pg-migrate migration that adds a priority column (integer, default 0) to the tasks table."
2. Ask Claude to update the API: "Update the POST and PATCH /tasks endpoints to accept and return the priority field."
3. Ask Claude to update the UI: "Add a priority dropdown to the task creation form and display it in the task list."

### Debugging a Runtime Error

1. Ask Claude to run the app: "Run `docker compose up` and tell me what errors appear."
2. Ask Claude to investigate: "The API is crashing with 'Cannot read property X of undefined'. Find where this happens and fix it."
3. Ask Claude to verify: "Run the app again and confirm the error is gone."

### Reviewing Code Quality

1. Ask Claude to check for N+1 queries: "Is there any N+1 query risk in the API? Check all database calls."
2. Ask Claude to review error handling: "Review the API's error handling. Are there cases where the server could crash?"
3. Ask Claude to suggest improvements: "Are there any security issues or best practice violations in `src/api/index.js`?"
