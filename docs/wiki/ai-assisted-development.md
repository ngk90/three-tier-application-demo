# AI-Assisted Development

This three-tier application is designed to be understood and extended with AI agents like Claude Code. This page covers how to use Claude and other AI tools effectively with this codebase, including patterns for understanding the architecture, adding features across all three tiers, and working with migrations and infrastructure.

## Getting Started with Claude Code

[Claude Code](https://claude.ai/code) is a CLI tool that can read your codebase, run commands, edit files, and reason about multi-file changes. To get started:

```bash
npm install -g @anthropic-ai/claude-code
cd three-tier-application-demo
claude
```

Claude Code reads the project structure automatically and works best when you give it specific, scoped tasks rather than broad ones. The codebase is organized to make this easy: each tier (`src/web/`, `src/api/`, `src/db/`) has clear boundaries and responsibilities.

## Adding Features Across Tiers

The three-tier architecture has natural seam points at each layer boundary. When adding a feature, work one tier at a time and verify each before moving on:

### Workflow

1. **Database first** — Create a migration in `src/db/migrations/`
2. **API next** — Add the endpoint in `src/api/index.js` and test with curl
3. **Frontend last** — Wire up the UI in `src/web/app/`

### Example prompts

**Add a new endpoint:**
```
Add a DELETE /tasks/:id endpoint to the API and wire it up to a delete button in the frontend.
```

**Extend the schema:**
```
Add a due_date column to the tasks table. Create the migration, update the API to accept and return it, and show it in the UI.
```

**Add validation:**
```
Add input validation to the POST /tasks endpoint so that titles longer than 200 characters are rejected with a 422 status.
```

## Database Migrations

Migrations are stored in `src/db/migrations/` and use [node-pg-migrate](https://salsita.github.io/node-pg-migrate/). They are append-only — never edit an existing migration file; create a new one instead.

### Migration prompts

```
Create a node-pg-migrate migration that adds a priority column (integer, default 0) to the tasks table.
```

```
Show me all the migrations that have been applied and what schema they created.
```

## Best Practices for AI-Assisted Development

### Give context, not just commands

Instead of:
> "Fix the bug"

Try:
> "The PATCH /tasks/:id endpoint returns 200 even when the id doesn't exist. Fix it to return 404."

Claude can find the relevant file, but telling it which endpoint and what the expected behavior is saves a round-trip.

### Scope changes to one tier at a time

Work through the layers in order:

1. **Migration** — get the schema right first
2. **API** — add the endpoint and test it with curl
3. **Frontend** — wire up the UI

This makes it easier to debug and verify each change.

### Let Claude run the app

Claude Code can execute commands and observe output. For runtime issues, ask:

```
Run docker compose up and tell me what errors appear in the logs.
```

### Use it to write one-off scripts

For tasks like seeding data or inspecting the database:

```
Write a script that seeds the tasks table with 10 sample tasks using the API's POST /tasks endpoint.
```

### Ask for explanations before risky changes

Before a significant change (schema migration, refactor, authentication), ask Claude to explain its plan first:

```
Before you make any changes, explain your plan for adding user authentication to this app.
```

## Project Conventions for AI Agents

When working with Claude or other AI tools, keep these conventions in mind:

| Convention | Reason |
|-----------|--------|
| **Migrations are append-only** | Never edit an existing migration; create a new one. This ensures consistency across environments. |
| **The API is internal** | It's not exposed outside the Docker network; all external traffic goes through the web tier. |
| **Environment variables are the config boundary** | Connection strings, ports, and URLs are all passed via env vars. No hardcoded values. |
| **Node 22 / PostgreSQL 17** | Match these versions in any new Dockerfiles or dependencies. |
| **Next.js 16 / React 19** | The web tier uses recent versions; check `src/web/AGENTS.md` for breaking changes. |

## Workflow Example: Adding a Priority Field

Here's how you might use Claude Code to add a priority field to tasks:

1. **Start Claude Code** and ask:
   ```
   Create a migration that adds a priority column (integer, default 0) to the tasks table.
   ```
   Claude creates `src/db/migrations/1718500002000_add-priority.js`.

2. **Run migrations:**
   ```
   Run docker compose up and verify the migration applies successfully.
   ```

3. **Update the API:**
   ```
   Update the POST /tasks and PATCH /tasks/:id endpoints to accept and return a priority field.
   ```

4. **Update the frontend:**
   ```
   Add a priority dropdown to the task creation form and show priority in the task list.
   ```

5. **Test end-to-end:**
   ```
   Create a new task with priority 1, then update it to priority 2. Show me the API calls and the UI changes.
   ```
