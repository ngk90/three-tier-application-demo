# AI-Assisted Development

This project is designed to be understood and extended using Claude Code and AI agents. The codebase includes patterns and conventions that make it easy for AI tools to reason about the three-tier architecture, make multi-file changes safely, and add features end-to-end.

## Claude Code Setup

[Claude Code](https://claude.ai/code) is a CLI tool that reads your codebase, runs commands, edits files, and reasons about changes across multiple layers. Install it and open the repository:

```bash
npm install -g @anthropic-ai/claude-code
cd three-tier-application-demo
claude
```

Claude Code automatically discovers the project structure. It works best with specific, scoped tasks rather than broad requests. The tool can execute `docker compose` commands, read migrations, and test endpoints as it works.

## Common Tasks and Prompts

### Understanding the Architecture

Ask Claude to explain how data flows through the system:

- "Explain how a task flows from the browser through the web tier, to the API, and into the database."
- "What tables exist in the database and what are their schemas?"
- "Walk me through what happens when `docker compose up` runs, in order."

### Adding Features

Break feature requests into specific, scoped tasks:

- "Add a DELETE /tasks/:id endpoint to the API and wire it up to a delete button in the frontend."
- "Add a due_date column to the tasks table. Create the migration, update the API to accept and return it, and show it in the UI."
- "Add input validation to the POST /tasks endpoint so that titles longer than 200 characters are rejected with a 422 status."

### Database Migrations

Use Claude to create and verify migrations:

- "Create a node-pg-migrate migration that adds a priority column (integer, default 0) to the tasks table."
- "Show me all the migrations that have been applied and what schema they created."

### Docker and Infrastructure

Troubleshoot deployment and infrastructure issues:

- "The migrate service keeps restarting. Read the Dockerfile and docker-compose.yml and tell me why."
- "Add a .env.example file documenting all environment variables used across the three services."
- "Explain the Terraform in `src/infrastructure/` and what GCP resources it creates."

### Code Review

Ask Claude to audit code quality and performance:

- "Review the API's error handling. Are there cases where the server could crash or return an unhelpful error?"
- "Is there any N+1 query risk in the API? Check all database calls."

## Best Practices for AI-Assisted Development

### Give Context, Not Just Commands

**Instead of:**
> "Fix the bug"

**Try:**
> "The PATCH /tasks/:id endpoint returns 200 even when the id doesn't exist. Fix it to return 404."

Providing the endpoint name and expected behavior helps Claude find the relevant code faster and make the right fix.

### Scope Changes to One Tier at a Time

Three-tier applications have natural seams at layer boundaries. When adding a feature, ask Claude to work one layer at a time and verify each before moving on:

1. **Migration first** — get the schema right
2. **API next** — add the endpoint and test it with curl
3. **Frontend last** — wire up the UI

This approach reduces the risk of cascading failures and makes it easier to debug issues.

### Let Claude Run the Application

Claude Code can execute `docker compose up` and observe logs in real time. If something breaks at runtime:

```
Run docker compose up and tell me what errors appear in the logs.
```

This is faster than manual debugging and helps Claude understand the full system behavior.

### Use It to Write One-Off Scripts

For data seeding or inspection tasks:

```
Write a script that seeds the tasks table with 10 sample tasks using the API's POST /tasks endpoint.
```

### Ask for Explanations Before Changes

Before risky changes (schema migrations, refactors), ask Claude to explain its plan:

```
Before you make any changes, explain your plan for adding user authentication to this app.
```

This gives you a chance to review the approach and catch issues early.

## Project Conventions for AI Tools

These conventions help AI agents make safe, consistent changes:

| Convention | Details |
|-----------|---------|
| **Migrations are append-only** | Never edit an existing migration file; create a new one. This ensures consistency across environments. |
| **The API is internal** | The Express API (`src/api/`) is not exposed outside the Docker network. All external traffic goes through the Next.js web tier. |
| **Environment variables are the config boundary** | Connection strings, ports, and URLs are all passed via env vars. No hardcoded values. |
| **Node 22 / PostgreSQL 17** | Match these versions in any new Dockerfiles or dependencies. |
| **Version warnings in web tier** | `src/web/AGENTS.md` documents breaking changes in Next.js 16. Read it before writing frontend code. |

## Workflow Example

Here's a typical workflow for adding a feature with Claude Code:

1. **Understand the current state:**
   ```
   Show me the current tasks table schema and the API endpoints.
   ```

2. **Plan the change:**
   ```
   I want to add a priority field to tasks. Before making changes, explain your plan.
   ```

3. **Create the migration:**
   ```
   Create a node-pg-migrate migration that adds a priority column (integer, default 0) to the tasks table.
   ```

4. **Update the API:**
   ```
   Update the POST /tasks and PATCH /tasks/:id endpoints to accept and return the priority field.
   ```

5. **Test the API:**
   ```
   Run docker compose up and test the new endpoints with curl.
   ```

6. **Update the frontend:**
   ```
   Add a priority input to the task creation form and display it in the task list.
   ```

7. **Verify end-to-end:**
   ```
   Test the full flow: create a task with priority, update it, and verify it appears in the UI.
   ```
