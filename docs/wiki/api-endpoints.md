The three-tier application provides a simple REST API built with Express that manages tasks. The API runs on port 3001 and communicates with a PostgreSQL database. It exposes four endpoints for health checks, listing tasks, creating new tasks, and updating existing tasks.

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/health` | Health check — returns `{ "status": "ok" }` |
| GET | `/tasks` | List all tasks, ordered by creation time |
| POST | `/tasks` | Create a new task |
| PATCH | `/tasks/:id` | Update a task (mark complete or rename) |

## Health Check

**GET `/health`**

Returns the API health status. Use this to verify the API is running.

```json
{
  "status": "ok"
}
```

## List Tasks

**GET `/tasks`**

Retrieves all tasks from the database, ordered by creation time (oldest first).

**Response:**
```json
[
  {
    "id": 1,
    "title": "Buy groceries",
    "completed": false,
    "created_at": "2024-01-15T10:30:00Z"
  },
  {
    "id": 2,
    "title": "Write documentation",
    "completed": true,
    "created_at": "2024-01-15T11:00:00Z"
  }
]
```

## Create Task

**POST `/tasks`**

Creates a new task with the provided title. The title is required and must be a non-empty string.

**Request body:**
```json
{
  "title": "Learn Docker"
}
```

**Response (201 Created):**
```json
{
  "id": 3,
  "title": "Learn Docker",
  "completed": false,
  "created_at": "2024-01-15T12:00:00Z"
}
```

**Error (400 Bad Request):**
```json
{
  "error": "title is required"
}
```

## Update Task

**PATCH `/tasks/:id`**

Updates an existing task by ID. You can update the `completed` status, the `title`, or both. Omitted fields retain their current values.

**Request body (example 1 — mark complete):**
```json
{
  "completed": true
}
```

**Request body (example 2 — rename):**
```json
{
  "title": "Updated task name"
}
```

**Response (200 OK):**
```json
{
  "id": 3,
  "title": "Updated task name",
  "completed": true,
  "created_at": "2024-01-15T12:00:00Z"
}
```

**Error (404 Not Found):**
```json
{
  "error": "Not found"
}
```

## Implementation Details

The API is implemented in `src/api/index.js` using Express 5 and Node.js 22. All endpoints use the PostgreSQL connection pool from `src/api/db.js` to query the `tasks` table. Request bodies are parsed as JSON, and the API validates that task titles are non-empty strings before insertion or update.

## Accessing the API

When running locally with Docker Compose, the API service is not exposed to the host by default. You can:

- Access it through the web frontend (Next.js) at `http://localhost:3000`
- Temporarily expose port 3001 by modifying the `docker-compose.yml` file
- Make requests from within the Docker network using the service name `api:3001`

When deployed to Google Cloud Platform, the API runs on Cloud Run and is accessible via the service URL provided by Terraform.
