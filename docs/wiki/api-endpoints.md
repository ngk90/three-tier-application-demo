This application exposes a REST API built with Express that manages tasks in a PostgreSQL database. The API provides endpoints for listing, creating, and updating tasks, as well as a health check. All endpoints accept and return JSON, and the API runs on port 3001 (internal to the Docker network in local development).

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/health` | Health check; returns `{ "status": "ok" }` |
| GET | `/tasks` | List all tasks, ordered by creation time |
| POST | `/tasks` | Create a new task |
| PATCH | `/tasks/:id` | Update a task's completion status or title |

## GET /health

Returns the API health status.

**Response (200 OK):**
```json
{ "status": "ok" }
```

## GET /tasks

Retrieves all tasks from the database, sorted by creation time.

**Response (200 OK):**
```json
[
  {
    "id": 1,
    "title": "Buy groceries",
    "completed": false,
    "created_at": "2025-01-15T10:30:00Z"
  },
  {
    "id": 2,
    "title": "Write documentation",
    "completed": true,
    "created_at": "2025-01-15T11:00:00Z"
  }
]
```

## POST /tasks

Creates a new task with the provided title.

**Request body:**
```json
{ "title": "Learn Docker" }
```

**Response (201 Created):**
```json
{
  "id": 3,
  "title": "Learn Docker",
  "completed": false,
  "created_at": "2025-01-15T12:00:00Z"
}
```

**Error (400 Bad Request):**
- Missing or empty `title` field returns `{ "error": "title is required" }`

## PATCH /tasks/:id

Updates an existing task by ID. You can update the `completed` status, the `title`, or both.

**Request body (example 1 — mark as complete):**
```json
{ "completed": true }
```

**Request body (example 2 — rename):**
```json
{ "title": "Updated task name" }
```

**Response (200 OK):**
```json
{
  "id": 3,
  "title": "Updated task name",
  "completed": true,
  "created_at": "2025-01-15T12:00:00Z"
}
```

**Error (404 Not Found):**
- If the task ID does not exist, returns `{ "error": "Not found" }`

## Implementation Details

The API is implemented in `src/api/index.js` using Express 5 and Node.js 22. It uses a PostgreSQL connection pool (`src/api/db.js`) to execute queries. All endpoints validate input and return appropriate HTTP status codes.

- **Validation:** The POST endpoint requires a non-empty string `title`.
- **Ordering:** Tasks are returned in ascending order by `created_at`.
- **Updates:** The PATCH endpoint allows partial updates; omitted fields retain their current values.

## Accessing the API

In local development with Docker Compose, the API is not exposed to the host by default. You can:

1. Access it through the web frontend at `http://localhost:3000`
2. Temporarily expose port 3001 by modifying `docker-compose.yml`
3. Make requests from within the web container

In production (GCP), the API runs on Cloud Run and is accessed by the web frontend via an internal service URL.
