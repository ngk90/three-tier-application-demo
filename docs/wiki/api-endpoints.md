# API Endpoints

The Express REST API (`src/api/index.js`) provides a simple task management interface with four core endpoints. The API runs on port 3001 and uses PostgreSQL as its data store. All endpoints accept and return JSON, and the API includes basic validation for required fields.

## Health Check

| Method | Path | Description |
|--------|------|-------------|
| GET | `/health` | Returns API status |

**Response (200 OK):**
```json
{ "status": "ok" }
```

Use this endpoint to verify the API is running and healthy.

### Create a Task

| Method | Path | Description |
|--------|------|-------------|
| POST | `/tasks` | Create a new task |

**Request body:**
```json
{ "title": "Learn Express" }
```

**Response (201 Created):**
```json
{
  "id": 3,
  "title": "Learn Express",
  "completed": false,
  "created_at": "2025-01-15T12:00:00Z"
}
```

**Validation:**
- `title` is required and must be a non-empty string
- Returns 400 Bad Request if `title` is missing, not a string, or empty

### Update a Task

| Method | Path | Description |
|--------|------|-------------|
| PATCH | `/tasks/:id` | Update a task's completion status or title |

**Request body (either or both fields):**
```json
{ "completed": true }
```
or
```json
{ "title": "Updated task name" }
```
or
```json
{ "completed": true, "title": "Updated task name" }
```

**Response (200 OK):**
```json
{
  "id": 3,
  "title": "Updated task name",
  "completed": true,
  "created_at": "2025-01-15T12:00:00Z"
}
```

**Error responses:**
- Returns 404 Not Found if the task ID does not exist
- Partial updates are supported; omitted fields retain their current values

## Implementation Details

The API is implemented in `src/api/index.js` using Express 5 and connects to PostgreSQL via a connection pool defined in `src/api/db.js`. The pool reads the database URL from the `DATABASE_URL` environment variable.

All endpoints use parameterized queries to prevent SQL injection. Task data is persisted in the `tasks` table, which is created by database migrations in `src/db/migrations/`.

## Error Handling

The API returns standard HTTP status codes:
- **200 OK** — successful GET or PATCH
- **201 Created** — successful POST
- **400 Bad Request** — invalid input (e.g., missing required field)
- **404 Not Found** — task ID does not exist

Error responses include a JSON body with an `error` field describing the issue.

## Accessing the API

When running locally with Docker Compose, the API is not directly exposed to the host. Access it through:
- The web frontend (`src/web/`) which calls the API internally
- Temporarily mapping the port in `docker-compose.yml` (e.g., `ports: ["3001:3001"]`)

In production on Google Cloud Platform, the API runs on Cloud Run and is called by the web frontend service.
