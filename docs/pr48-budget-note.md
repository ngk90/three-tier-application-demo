## Using .editorconfig in This Project

A `.editorconfig` file helps maintain consistent coding style across different editors and contributors in this three-tier application project by defining shared formatting rules — such as indentation style, indent size, line endings, and trailing whitespace handling — that are automatically applied by any editor or IDE that supports the EditorConfig standard. In a project spanning multiple tiers (web frontend, API backend, and database migrations), where contributors may use VS Code, WebStorm, Vim, or other tools, `.editorconfig` ensures that a JavaScript file in `src/web`, a Node.js file in `src/api`, and a SQL migration in `src/db` all follow the same baseline formatting conventions without requiring each developer to manually configure their editor, reducing noise in diffs and making code reviews easier to focus on logic rather than style inconsistencies.
